# Contributing

Thanks for your interest in contributing to checkin-demo.

## Reporting issues

Open an issue in the GitHub issue tracker. Describe what you expected, what happened, and how to reproduce it.

Do not report security vulnerabilities in a public issue. See [SECURITY.md](SECURITY.md) instead.

## Proposing changes

1. Fork the repository.
2. Create a branch from `main` for your change.
3. Make your changes and commit them.
4. Open a pull request against `main`.

## Commit and pull request expectations

- Keep each pull request focused on a single change.
- Write clear commit messages that explain what changed and why.
- Describe the purpose of the change in the pull request description, and link any related issue.
- Follow the rules in [SECURITY.md](SECURITY.md).

## Security

Changes must follow the rules in [SECURITY.md](SECURITY.md). Never include secrets or personal data in commits, issues, or pull requests.
